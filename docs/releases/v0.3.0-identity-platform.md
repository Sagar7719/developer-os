## 1. Overview

Release **`v0.3.0`** delivered the production-grade **Identity Platform Foundation** for **Developer OS (Brand: Sagar.dev)**. It implemented user database schemas, dual JWT authentication (Access & Refresh tokens), bcryptjs password hashing, SHA-256 refresh token database hashing, `UserDTO` output sanitization, Winston audit logging, and Role-Based Access Control (RBAC).

- **Git Tag**: `v0.3.0`
- **Related Spec**: Request for Comments `RFC-003: Identity Platform`
- **Release Date**: August 2026

---

## 2. Milestone Objectives

1. Design Mongoose `User` model with email uniqueness, `{ select: false }` password protection, and role enum (`Roles.ADMIN`, `Roles.USER`).
2. Build dual-token authentication model: short-lived Access Tokens (15m, Bearer header) and long-lived Refresh Tokens (7d, `httpOnly` cookie).
3. Store ONLY SHA-256 hashes of refresh tokens in MongoDB to eliminate database breach token replay risks.
4. Implement Refresh Token Rotation and automatic panic session revocation upon token reuse detection.
5. Create `UserDTO` serializer ensuring zero exposure of passwords or internal token hashes.
6. Integrate Winston audit logging (`logger.info('[Audit] ...')`) tracking login, logout, and token rotation without logging secrets.

## 3. Features & Infrastructure Delivered

```mermaid
flowchart LR
    AuthAPI[/api/v1/auth Routes] --> AuthCtrl[Auth Controller]
    AuthCtrl --> AuthSvc[Auth Service]
    AuthSvc --> Bcrypt[bcryptjs Hashing]
    AuthSvc --> JwtUtil[JWT Access/Refresh Signer]
    AuthSvc --> UserDTO[UserDTO Sanitizer]
    AuthSvc --> UserRepo[User Repository]
    UserRepo --> Mongo[(MongoDB Atlas)]
```

- **Mongoose User Model ([`user.model.js`](../../apps/server/src/models/user.model.js))**: Configured with normalized email index, role enum, and JSON serialization transforms stripping sensitive fields.
- **UserRepository Layer ([`user.repository.js`](../../apps/server/src/repositories/user.repository.js))**: Encapsulated queries for email lookup, ID lookup, creation, and SHA-256 refresh token hash management.
- **AuthService Domain ([`auth.service.js`](../../apps/server/src/services/auth.service.js))**: Business logic for registration, authentication, token pair issuance, refresh token rotation, and audit logging.
- **Auth Utilities**:
  - [`jwt.util.js`](../../apps/server/src/utils/jwt.util.js): Signs & verifies access/refresh tokens using environment expiration configs.
  - [`password.util.js`](../../apps/server/src/utils/password.util.js): Wraps `bcryptjs` password hashing and SHA-256 `hashToken()` token digest generation.
- **Middlewares & Role Security**:
  - [`auth.middleware.js`](../../apps/server/src/middleware/auth.middleware.js): Validates Bearer access tokens and attaches `req.user`.
  - [`role.middleware.js`](../../apps/server/src/middleware/role.middleware.js): Enforces RBAC permissions (`authorize(Roles.ADMIN)`).
- **Cookie Strategy ([`cookie.config.js`](../../apps/server/src/config/cookie.config.js))**: Centralized options (`httpOnly: true`, `secure: config.isProduction`, `sameSite: strict`, `path: /api/v1/auth`).
- **Authentication Endpoints**: Published `/api/v1/auth/register`, `/api/v1/auth/login`, `/api/v1/auth/logout`, `/api/v1/auth/refresh-token`, and `/api/v1/auth/me`.

---

## 4. Architecture Impact

- Added authentication and authorization layer to Developer OS.
- Enforced Refresh Token Rotation protecting against session theft and replay attacks.
- Standardized `UserDTO` sanitization across all controller responses.
- Replaced native `bcrypt` with pure JavaScript `bcryptjs` for Windows platform cross-compatibility.

---

## 5. Breaking Changes & Migration Notes

- **Breaking Changes**: None (Backwards-compatible addition under `/api/v1/auth`).
- **Migration Notes**: `.env` and `apps/server/.env` MUST define `JWT_ACCESS_SECRET`, `JWT_ACCESS_EXPIRES_IN`, `JWT_REFRESH_SECRET`, and `JWT_REFRESH_EXPIRES_IN`.
